# Saved local venture intake — Prompt 2

`venture-intake:1` is a separate strict local assertion contract. Research interchange remains 0.2.1 and historical app inputs remain 1/2. Local descriptions are `local_user_assertion`; optional claims are `user_supplied_source_attribution_unreviewed`, even when a URL/publisher is supplied. They are not authenticated publisher reports, factual acceptances or independent judgments. Missing legal, buyer/payer, procurement, funding and outcome facts remain unverified. No intake data is inserted into the ten-venture retrieval corpus.

Use **Add venture** to enter a name, aliases, description and optional attributed sources. Each source retains its URL, title, publisher, locator, responsibility, retrieval day and explicit publication precision. Unknown occurrence dates remain unknown. Existing research subjects may be selected as a query context, not merged or accepted. The original research adapter, mapping audit and exploration/accepted policies remain authoritative for imported evidence.

Saving uses migration 005's immutable draft/revision tables. Initial creation, an entire revision and its retry key commit atomically. Reusing a request ID with different input is refused; exact retries return the existing draft. Edits require the last observed revision and append history, rather than replacing evidence. Stale edits return a conflict. Foreign keys and SQLite rollback protect against partial saves. Cross-origin browser writes are refused; other runtime evidence endpoints remain read-only. Bootstrap/migration are explicit, not API-startup side effects.

`GET /api/intake/drafts`, `GET /api/intake/drafts/{id}`, `POST /api/intake/drafts`, and `POST /api/intake/drafts/{id}/revisions` provide persistence. `GET /api/intake/duplicates?q=...&aliases=...` previews name/alias candidates across application, research and drafts without resolving identity. Saved input survives reload; unsaved form input is retained locally and failures leave it available to retry. List views show up to the latest 100 drafts and total count.

`POST /api/intake/drafts/{id}/compare` accepts exploration/accepted policy and product/customer or commercialisation mode. It uses the saved description and user-supplied source-attribution text as a literal query, never as corpus evidence. The separately versioned `intake-b0-query-1.0` wrapper retains B0 normalization, IDF, minimum overlap and coverage rules; it explicitly records query fields, revision hash, policy, excluded IDs, corpus digest and deterministic run ID. It ranks full-precision scores and rounds for display. B0 itself and historical golden results are unchanged. The comparison table includes the query draft with missingness and unreviewed status.

Only a genuinely resolved stored research-to-app mapping excludes the selected query subject. Name candidates and proposed links do not establish identity. A selected research query context is a user request about that subject, not an accepted correspondence/legal identity for a new venture. Accepted-only mode never promotes local assertions. Missing eligible records cause explicit abstention, not invented relevance or irrelevance.

Backend and browser regressions use disposable databases and conspicuously synthetic assertions/actors. They verify save/reload/reopen, duplicate aliases, source/date refusal, stale revisions, retry equality, rollback, persistence failure, same-subject exclusion, corpus isolation and accepted-only safeguards. No example draft or resolution is inserted into the user's database by the release. New mutations are serialized in the shared disposable browser-test service to avoid unrelated test writes invalidating comparison snapshot/replay checks.
