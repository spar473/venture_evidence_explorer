The exact supplied `expanded-discovery-0.1` packet and research/validation notes are preserved under `research/expanded-discovery/`. A new strict adapter schema (`Discovery_staging_v1.schema.json`) describes the packet's actual keys and optional variants. It is not research interchange 0.2.1 or an application seed. Unknown keys, non-finite/duplicate JSON, duplicate IDs, bad references and represented chronology are refused before data writes. All original fields and bytes remain available; absent fields are not defaulted to business facts.

The supplied grain is **274 name-normalized leads**, **27 organisations/source families**, **42 sources**, **365 listings**, **4 targeted outcome reports**, **2 explicit name links** and **16 reconciliation/scope cases**. These are not accepted unique NZ ventures or a historical national population. No source text was freshly researched in this coding stage. Existing pilot/portfolio/outcome depth labels retain their original meaning; no-update records do not become failed companies.

Migration 006 stores an isolated immutable staging graph with raw import/hash, membership, typed reference edges, decision documents and review records. Original source IDs and discovery IDs are preserved. Name links/cases lacking editorial IDs receive stable content hashes, not array-position IDs. Import graph and ledger share one explicit transaction. Exact repeats preserve every row; immutable semantic conflicts and injected failures roll back. Raw source/publication dates, null investment dates/fund identities and targeted outcome date precision/basis remain distinct. A current portfolio listing is not a historic investment event, cheque, legal vehicle or same-round co-investment.

The **Discovery queue** supports name search, source family, candidate review state, evidence gap and reported-outcome period. Period filters use explicit dated outcome reports only; they do not infer founding/investment dates from publication or retrieval. Unknown dated activity is a separate filter. Detail views retain all overlapping listings, sources/access limitations, actual name links, possible aliases, date/conflict cases and explicit missing fields. Matching labels do not merge identities. Candidate/reference CSVs retain stable IDs, import hash, review disposition and exact `raw_json`; seven collection exports have one row per record, not an inflated count per overlapping family.

Current production review decisions are absent: **274 staged, 0 promoted, accepted NZ population unknown**. Optional `discovery-decisions:1` CLI sidecars record genuinely supplied identity/NZ-inclusion/period decisions, with actor/role, date, subject-correct source IDs, explicit dated evidence, rationale and an optional target research subject. The representation cannot authenticate a reviewer. Assistant decisions, missing actors, future evidence and unrelated sources are refused; raw decision input and history are retained. No synthetic review fixture enters the real database.

Promotion is a **dry run only**. A portfolio listing cannot be invented into atomic source observations. Resolved identity, dated NZ inclusion and period-scope decisions must exist, and a separately supplied research 0.2.1 packet must pass the existing research adapter and have matching typed acceptance provenance. `--research-packet FILE` exercises that adapter path; missing/rejected/source-checked-only inputs remain withheld. Even a ready preview performs zero writes; no promotion endpoint is enabled for this milestone. Neither discovery nor intake contributes evidence to B0 or accepted-only matching.
