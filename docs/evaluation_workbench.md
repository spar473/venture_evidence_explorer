# Honest frozen evaluation — Prompt 4

The original six development queries and blank `evaluation/judgments.csv` remain unchanged. `evaluation/protocol-v1/` adds a separate versioned task/review protocol. Candidate selections are inspection hypotheses, never positive/negative relevance labels. Source-backed seed alternatives include Formus Labs, AtlasOR and the IVF tool for imaging/workflow questions; Space Optics/BioSleeve for hardware-context inspection; Pollsport for consumer/sponsor questions; and Agriphage for farm-health contrasts. Query-specific inclusion criteria, distractor suggestions and evidence gaps are exported with their stable IDs. Actual source entailment and task usefulness still require human review.

All existing identities/tasks belong to one development cohort to avoid pretending related seed queries are independent. `heldout_unseen_cohort_01` reserves a distinct held-out ID/group with no invented query or profiles and an explicit `awaiting_evidence` reason. Running held-out evaluation yields no executed tasks/metrics. Genuine independent held-out venture/task research remains a data prerequisite. Duplicate tasks, overlapping query groups or related venture identities across splits are refused. Two contrasting dossiers are not a relevance benchmark.

```sh
python scripts/evaluation_workbench.py freeze --db outputs/venture_evidence.sqlite --output-dir outputs/frozen-evaluation --as-of 2026-11-18
python scripts/evaluation_workbench.py review-materials --bundle outputs/frozen-evaluation --output-dir outputs/human-review
python scripts/evaluation_workbench.py run --bundle outputs/frozen-evaluation --output outputs/development-run.json
python scripts/evaluation_workbench.py run --bundle outputs/frozen-evaluation --split held_out --output outputs/held-out-status.json
python scripts/evaluation_workbench.py compare --left outputs/method-a.json --right outputs/method-b.json --output outputs/paired-comparison.json
```

Freeze creates a consistent SQLite backup, canonical eligible corpus projection, unchanged task definitions and a checksummed manifest with physical/logical input hashes, policy/evidence versions, method parameters, code hashes and applied migrations. Source inspection/review chronology cannot be after the stated research-as-of date. That date is not a historical archive-availability claim. Inputs and source/method versions are checked on every run; database and canonical eligible projection must agree. Freeze/review-material exports refuse nonempty output locations so human work or earlier experiments cannot be overwritten.

The review export contains sixty **blank** task/candidate rows plus empty reviewer registry, factual-audit, adjudication and task-time/usefulness templates. No reviewer names, grades, timestamps, consent or observations are invented. A real reviewer registry must declare actual ID, human role and independence. Independence is recorded rather than inferred from ownership/title, and the tool cannot authenticate the declaration. Human grades require 0–3, an evidence-based rationale, selected same-subject observation IDs and a valid review date. Wrong/duplicate IDs, assistant/non-human declarations, future dates, unselected evidence and malformed/incomplete numeric inputs are refused. Blank grades remain unjudged, not zero. Independent disagreements retain each reviewer's original grade, rationale and independence; no adjudication or consensus is synthesized.

Per-reviewer nDCG@3 uses gain `2^grade−1` and requires complete eligible-corpus judgments; zero ideal gain produces null with its own reason. Precision counts grades ≥1 and divides by the number actually returned (fewer than three is explicit). Empty results have no relevance score. Per-query aggregate metrics stay null without an explicit adjudication; reviewer-specific measurements remain inspectable. No recall from incomplete judgments is reported. Operational result coverage/abstention is distinct from relevance. Optional factual-audit input counts only actual provided, registered human classifications with rationale/provenance; automatic reference/subject/source checks are not factual entailment judgments. Task-time/usefulness observations remain blank until collected.

Runs report SQL counts separately from warm offline latency including JSON serialization, and separately time full-store digest construction. Environment, corpus size, method/policy and repeat count are disclosed; browser/network transport is excluded. No performance result is hard-coded. The current implementation only runs B0; comparison tooling can assess separately produced method reports on identical frozen inputs, eligibility, policy, split and human labels. It recomputes relevance metrics from reported grades/rankings and refuses unsupported numeric claims. Different source/method manifests are allowed only when frozen data hashes/eligibility/task inputs and judgments are identical. No second unimplemented method is presented as evaluated.

A paired cluster bootstrap helper operates over declared independent query groups only when at least eight groups have actual paired outcomes. This minimum is a protocol choice, not proof of generalisation. The supplied development cohort has one group and no real labels, so intervals remain null. Synthetic numerical fixtures test metric/bootstrap code only and never enter research, review materials or empirical claims.

Current outputs correctly say `not_evaluated` / `judgments_missing`, with null relevance metrics and explicit held-out/data gaps. Real human relevance/factual review, adjudication, independent held-out tasks and analyst usefulness/time observations remain pending. Statistical generalisation and product usefulness are not established by passing software tests.
