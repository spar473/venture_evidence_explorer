## Milestone gates (sequence, not promised dates)
M0 — This pack: ten sourced historical records, specification and local data slice.
M1 — Owner reviews identities and programme relationships. Enumerate full award lists for selected years; maintain pending matches and missing sources.
M2 — At least one additional dated source for selected ventures; reviewed product/customer/pathway fields. Define the first useful query with a prospective user.
M3 — PostgreSQL schema migrations, raw/curated separation, structured logs and incremental import. Confirm old observations survive an update.
M4 — Power BI report: cohort coverage, programme events, documented connections and source freshness. Clearly identify observation counts and unknowns. Do not chart fabricated success rates.
M5 — Local profile/search page, filter/keyword baseline, at most three comparisons with differences and evidence.
M6 — Blind relevance review, structured matching, then semantic retrieval if justified. Publish baselines and failure cases.
M7 — AI brief generation over eligible observations, groundedness audit, feedback from willing users.
M8 — Optional community pathway mapping, experiment suggestions and a reviewed external-proposal adapter for MCDA Studio.

## Minimum credible portfolio handoff
A reproducible data pipeline, a meaningful SQL analysis, an inspectable report, a narrowly useful search workflow and an honest evaluation. A screenshot or chat interface alone does not establish these capabilities.

## Data expansion
Start with 2024–2026 challenge award lists, then older named cohorts. No arbitrary target of hundreds of entities before quality checks work. Track attempted coverage, unresolved entities and source availability. A complete award cohort can describe programme recognition; it still cannot estimate the causal impact of participation or general startup success.
